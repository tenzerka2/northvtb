# NORTH

Работающий sandbox backend для ограниченных финансовых полномочий цифровых агентов. Владелец подтверждает точные условия покупки, детерминированный Policy Engine проверяет предложение, а одноразовый подписанный Grant разрешает создать ровно одну платёжную команду. Агент не получает банковские реквизиты или доступ к PaymentProvider.

Go modular monolith, PostgreSQL, OpenAPI 3.1, Docker Compose. Адаптивный интерфейс NORTH перенесён из Figma и встроен в Go-бинарник; отдельный frontend-сервер не нужен. Это MVP для демонстрации банковской архитектуры: реальные платежи, банковский OIDC и сертифицированная криптография не подключены.

Материалы для конкурса и следующего этапа: [тексты заявки, исследование, пилот, экономика и задание на интерфейс](docs/submission/README.md). Источник интерфейса: [макеты Figma](https://www.figma.com/design/38DYWiEZUCl7H1QRz54KIF/Untitled). Видео и презентация готовятся отдельно.

## Один воспроизводимый запуск

Нужны Docker с Compose, Python 3 и make. Из корня репозитория выполните:

```sh
make demo
```

Команда создаёт локальные случайные секреты, поднимает PostgreSQL, применяет миграции, создаёт отдельные учётные записи приложения и sandbox-провайдера, загружает предложения PS5 и монитора, запускает API и проходит сценарий через HTTP. Повторный запуск сохраняет существующие секреты и данные. Контейнерная сборка рассчитана на linux/amd64; на Apple Silicon задайте `DOCKER_DEFAULT_PLATFORM=linux/amd64` для этого запуска.

Ожидаемый результат: 96 900 ₽ → DENY; 81 000 ₽ у непроверенного продавца → DENY при строгом мандате; 82 990 ₽ → ALLOW → SUCCEEDED → CONSUMED 1/1. Повторное исполнение блокируется. Для нового действующего Grant подмена 82 990 ₽ на 92 990 ₽ возвращает `TRANSACTION_HASH_MISMATCH`. Демо также проверяет разделение ролей, кражу полномочий другим агентом, идемпотентный повтор и возврат без восстановления лимита.

API доступен на `http://127.0.0.1:8080`. Обычная остановка: `docker compose down`; том с данными сохраняется. `.env` и `.secrets/signing.seed` имеют ограниченные права и исключены из Git и Docker build context. Сохраняйте их вместе с базой: потеря signing seed делает прежние подписи непроверяемыми. Не меняйте секреты существующего sandbox произвольно — автоматическая ротация ключей не реализована.

## Интерфейс на ПК и телефоне

После `make demo` откройте **http://127.0.0.1:8080**. Для входа используйте значение `NORTH_OWNER_TOKEN` из локального `.env`. Не публикуйте этот файл или ключ. Backend хранит сессию в HttpOnly SameSite-cookie; ключи владельца и агента не сохраняются в браузере.

Создайте поручение, подключите агента «Закупки», оставьте монитор Dell UltraSharp U2723QE и лимит 85 000 ₽. После подтверждения поручения доступны три предложения:

- DNS, 82 990 ₽ — разрешено условиями.
- Технопарк, 79 500 ₽ — новый поставщик, требуется ваше согласие на конкретную покупку.
- Ситилинк, 89 900 ₽ — блокировка по лимиту, согласие не может её отменить.

Интерфейс включает черновик и активацию поручения, предложения, подтверждение, отзыв поручения/агента, результат оплаты, историю и JSON-выгрузку. Суммы и статусы читаются из PostgreSQL. Просмотр предложений не резервирует разрешение. После отправки оплаты интерфейс опрашивает статус, не создавая повторную покупку. При сетевой ошибке повтор использует прежний Idempotency-Key. Сессии действуют восемь часов и сбрасываются при перезапуске сервера.

Это локальный sandbox: агент моделируется сервером, каталог фиксирован, доставка физически не выполняется. JSON-сведения об операции не являются кассовым чеком. Вместо нарисованного в макете банковского баланса показывается реальный суммарный лимит поручений. Адрес и обещание даты доставки убраны, поскольку backend их не исполняет. Списки показывают до 200 последних записей, журнал — до 200 событий. Отзыв блокирует новые действия, но не гарантирует отмену уже отправленной оплаты.

`/ui/*` — закрытый same-origin BFF только для sandbox; публичный агентский API `/v1/*` сохраняется. Для размещения за TLS-прокси нужен отдельный production session/auth adapter и настройка доверенного origin; текущий вариант предназначен для локального запуска.

## API для интерфейса

Полный контракт: [api/openapi.json](api/openapi.json). Генератор: `make contract`. Владелец использует `NORTH_OWNER_TOKEN` из локального `.env`; зарегистрированный агент получает отдельный bearer credential. В запросах изменения нужен `Idempotency-Key`. Повтор с тем же ключом и телом возвращает сохранённый результат; изменённое тело — 409. Для текущего состояния используйте GET, поскольку сохранённый ответ команды может содержать PENDING.

Основные маршруты: создание/отзыв агента, draft/approve/replace/revoke мандата, каталог предложений, авторизация, исполнение Grant, подтверждение risk challenge, чтение мандата/платежа/возврата, журнал владельца с деталями предложений и проверок, полный возврат и подписанный callback. Замена мандата создаёт новую версию и отзывает прежнюю атомарно; новая версия требует нового подтверждения.

Все суммы — целые копейки, все времена в JSON — UTC Unix seconds. Финансовые решения не используют LLM. Интерфейс optional Intent Compiler может предложить draft, но не может подтвердить его. При `ASK_USER` владелец подтверждает точный transaction hash, после чего агент повторяет запрос с новым idempotency key. Согласие не отменяет ограничение суммы, привязку агента, срок действия или требование проверенного продавца.

## Что проверяется

```sh
make test
make vet
make build
make schema-test   # PGHOST/PGUSER/PGPASSWORD/PGDATABASE: отдельная тестовая БД
make contract
```

Для PostgreSQL Go integration tests задаются `NORTH_TEST_DSN`, `NORTH_TEST_PROVIDER_DSN` и отдельный `NORTH_TEST_ADMIN_DSN`. Без первого адреса интеграционные тесты явно SKIP; это не считается доказательством их прохождения. CI запускает их на PostgreSQL 17 с ограниченными ролями и отдельно выполняет HTTP demo и весь `make demo` через Compose.

Проверки включают 32 параллельных выдачи Grant и 32 попытки его потребления; резервируется одна покупка и создаётся одна команда. Тестируются подписи, подмена транзакции, отзыв/истечение полномочий, идемпотентность, изолированный sandbox provider, таймаут после фиксации списания, восстановление, callback, возврат, risk continuation, tamper-evident audit и конкурентная доставка outbox. Фактические CI результаты: [docs/status.md](docs/status.md).

## Эксплуатация и границы

`/healthz` проверяет процесс, `/readyz` — зависимости. Без `NORTH_MODE=sandbox` стартует только foundation health service с readiness 503. В sandbox работает durable worker для платежей, возвратов, истечения полномочий и outbox. UNKNOWN никогда не освобождает резерв; повторы используют ту же платёжную идентичность. Отзыв до SUBMITTED блокирует отправку. После фиксации SUBMITTED нельзя обещать отмену внешней операции — результат устанавливается сверкой.

Структурированные логи включают request ID и trace ID, не содержат bearer credentials или тела финансовых запросов. OpenTelemetry экспортирует HTTP/worker spans при настройке `OTEL_EXPORTER_OTLP_ENDPOINT`; без коллектора сервис работает локально. `/metrics` доступен владельцу и отдаёт Prometheus-метрики, совместимые со сбором OpenTelemetry Collector. Ограничители запросов имеют ограниченную память; финансовая корректность от них не зависит.

Outbox доставляется в долговечный локальный `event_inbox` с дедупликацией. Внешняя шина пока не подключена. Hash chain обнаруживает изменение истории; против полной переписи привилегированным администратором нужна внешняя контрольная точка.
